# Team Practice Notes

## Pull Request Workflow
- Pull the latest `main` branch (`git pull origin main`) before starting a new branch.
- Keep each pull request small and focused on one change.
- Run `git status` before committing and stage only the files you meant to change.
- Never commit `.env` or any file containing passwords or connection strings.
- Include testing notes in every pull request.
- Ask for review in the team Microsoft Teams channel when a PR is ready.
